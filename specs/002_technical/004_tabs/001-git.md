# Changes Tab

Changes Tab绑定当前Space，并将repository discovery、status collection与按文件diff读取组合成只读变更审阅视图。

## Discovery范围

AppBackend为active Space的canonical root维护一个`ActiveRootContext`。绑定同一root的Spaces共享`data.db`中的repository和status cache。

首版使用固定策略：

```text
depth 0   Space root
depth 1   Space root的直属子目录
skip      .git、node_modules、directory symlink
marker    .git directory或.git file
```

扫描深度不提供用户配置。物理上位于范围内的submodule或linked worktree可能包含`.git` file，并作为普通repository处理。首版不建立特殊关系图。

## Discovery流程

1. canonicalize Space root，创建或复用ActiveRootContext，并加载repository cache。
2. 对Space root执行Git probe；只有`--show-toplevel`等于canonical Space root时才接受。
3. 枚举直属子目录，跳过固定忽略项和directory symlink。
4. 对存在`.git` marker的候选目录调用Git确认repository root。
5. 使用canonical repository root去重并按Space-relative path排序。
6. 以一次tree replacement更新UI和`git_repositories_cache`。

不存在working tree的bare repository不进入首版结果。Space root外部的parent repository和linked worktree不进入扫描范围。

## 增量协调

- `FileWatchAdapter`监听root直属目录和`.git` marker变化，并以短debounce重新运行discovery。
- 每个已发现repository监听working tree和Git metadata的状态相关变化。
- Space激活、手动Refresh和watcher overflow触发协调扫描。
- 每次扫描在ActiveRootContext内存中创建新的`scanGeneration`；旧generation结果被丢弃，generation不写入`data.db`。
- inactive root停止watcher和status tasks；再次激活时先显示cache，再扫描最新状态。

## VS Code参考

首版采用VS Code的保守默认思路：workspace root probe、直属子目录扫描、默认忽略`node_modules`、监听`.git`变化和canonical path去重。

## Status collection

`GitStatusService`为每个已发现repository生成完整只读snapshot：

```ts
interface GitStatusSnapshot {
  spaceId: string;
  repositoryId: string;
  scanGeneration: number;
  branch?: string;
  upstream?: string;
  ahead: number;
  behind: number;
  files: GitFileChange[];
  capturedAt: number;
  error?: string;
}

interface GitFileChange {
  path: string;
  originalPath?: string;
  indexStatus: string;
  worktreeStatus: string;
  kind:
    | "modified"
    | "added"
    | "deleted"
    | "renamed"
    | "copied"
    | "type-changed"
    | "untracked"
    | "conflicted";
}
```

每个repository通过argv直接执行：

```text
git -C <repository-root> status --porcelain=v2 -z --branch --untracked-files=all
```

`-z`保留空格、换行和非ASCII path；parser使用平台path bytes/`OsString`，显示层执行可逆编码。porcelain v2提供index/working-tree双状态、rename source和branch metadata。

## Status调度

- discovery结果为新增repository排队，worker pool限制并发Git processes。
- repository变化经过短debounce后刷新status。
- Git Tab focus、Space恢复和watcher overflow触发freshness probe。
- 同一repository同时最多运行一个probe；运行期间再次dirty会在完成后排队一次新probe。
- 每个probe携带`scanGeneration + repositoryId`；generation不匹配的结果被丢弃。
- 前端按`repositoryId`幂等upsert完整snapshot。
- `git_status_cache`保存最近snapshot，让Git Tab先渲染cache再协调实时结果。

## Diff读取

renderer通过`readGitDiff`按文件请求diff：

```ts
interface ReadGitDiffRequest {
  spaceId: string;
  repositoryId: string;
  path: string;
}

interface GitFileDiff {
  repositoryId: string;
  path: string;
  originalPath?: string;
  additions: number;
  deletions: number;
  binary: boolean;
  truncated: boolean;
  hunks: GitDiffHunk[];
}

interface GitDiffHunk {
  header: string;
  oldStart: number;
  oldLines: number;
  newStart: number;
  newLines: number;
  lines: GitDiffLine[];
}

interface GitDiffLine {
  kind: "context" | "added" | "deleted" | "meta";
  oldLine?: number;
  newLine?: number;
  content: string;
}
```

AppBackend从当前root的Git snapshot解析`repositoryId + path`，再把已确认的repository与change交给Git adapter。adapter重新校验canonical repository root位于Space root内。

tracked文件通过argv直接执行：

```text
git -C <repository-root> diff --no-ext-diff --no-color --unified=3 <baseline> -- <path>
```

普通repository使用`HEAD`作为baseline；初始repository使用Git empty tree。untracked文件由adapter读取working tree内容并生成单个added hunk。parser读取file header、hunk ranges、行类型和行尾提示，并统计additions/deletions。binary和超过4 MiB展示上限的结果通过DTO标记。

renderer限制并发diff请求数，使用snapshot generation丢弃过期结果。每个文件将DTO投影为双行号、增删marker和line background；`LanguageDescription.matchFilename`按目标path加载CodeMirror language support，Lezer parser与`classHighlighter`生成安全的token spans，CSS token映射沿用File Editor语义色。

renderer将diff rows按64行组成固定内在高度的chunk，并通过`content-visibility`与layout/paint containment让WebView只布局视口附近的chunk。全局内容宽度由各行的monospace显示列数推导，使未布局chunk仍保留稳定的水平滚动范围。文件折叠使用零高度`content-visibility: hidden` box，滚动选中文件通过视口命中测试解析，避免折叠后遍历全部文件并读取几何信息。

## Changes projection

- 每个已发现repository对应一个section，包括clean repository。
- section按Space-relative repository path排序；名称冲突时显示相对路径。
- status error归属对应section，其他repositories继续更新。
- 左侧按repository顺序投影file diff sections；右侧投影filterable file navigation。
- 左侧file header、右侧file navigation与Files Tab调用同一个资源图标解析和SVG工厂；Git status作为行尾语义色短代码投影。
- 单击导航文件通过稳定的`repositoryId + path`定位左侧section。
- repository collapse、file diff collapse和选中文件保存在Git Tab state中。
- service API包含`listStatus`、`subscribeStatus`、`refreshStatus`和`readGitDiff`。
